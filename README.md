# Forja

Переводит PHP-методы в C с помощью модели (Claude по API или локальной), проверяет, что C-версия ведёт себя так же, и после этого подменяет вызовы через Zend FFI. Вызывающий код не меняется. Всё, что перевести нельзя или не удалось проверить, продолжает работать как обычный PHP.

## Как это работает

1. Вы помечаете метод атрибутом `#[AccelerateToC]`.
2. `vendor/bin/forja` отправляет метод модели и получает C-код-кандидат.
3. Кандидат компилируется и в отдельном процессе сравнивается с PHP-методом на ~1000 входах.
4. Только если результаты совпали, C-файл кладётся в проект: `forja/src/App/Report/total.c`, а его контрольная сумма — в `forja/forja.lock.json`.
5. Вы коммитите `forja/src` и `forja.lock.json`. Остальные машины собирают модуль из этих файлов и модель не вызывают.

```php
use Forja\Attributes\AccelerateToC;

final class Words
{
    /** @return array<string, int> */
    #[AccelerateToC]
    public static function counts(string $text): array
    {
        // обычный PHP
    }
}
```

```bash
vendor/bin/forja
```

После этого `Words::counts($text)` в любом месте приложения выполняет C-версию. Обёрток и регистрации в контейнере не нужно: пакет подключается через автозагрузчик Composer, поэтому одинаково работает в Laravel, Symfony и без фреймворка.

## Одинаковый код на всех машинах

Модель не детерминирована: два запроса с одним и тем же методом дают разный C-код, и добиться побайтно одинаковой генерации на разных машинах нельзя. Поэтому Forja устроена как Composer:

| | Composer | Forja |
|---|---|---|
| разработчик меняет состав | `composer update` | `vendor/bin/forja` |
| фиксируется в репозитории | `composer.lock` | `forja/src/` + `forja/forja.lock.json` |
| CI и продакшен | `composer install` | `vendor/bin/forja --frozen` |

`--frozen` никогда не обращается к модели. Он берёт C-файлы из репозитория, сверяет их sha256 с `forja.lock.json`, компилирует и заново проверяет против PHP. Изменённый без обновления lock-файла исходник отклоняется; метод, для которого в репозитории нет перевода текущей версии, остаётся на PHP со статусом `missing`.

```json
"scripts": { "post-install-cmd": ["forja --frozen"] }
```

Режим также включается переменной `FORJA_FROZEN=1`.

Метод, который не менялся, сохраняет свой перевод, даже если вы сменили модель по умолчанию или обновили пакет: повторная генерация дала бы другие байты при том же поведении. Заново спросить модель можно явно: `vendor/bin/forja --force`.

`forja/build/` (библиотеки, копии PHP-файлов, отклонённые кандидаты) создаётся на каждой машине и исключён из git автоматически.

## Что переводится

Параметры и результат могут быть любыми значениями из `null`, `bool`, `int`, `float`, `string` и массивов: списков, ассоциативных, вложенных. Типы могут быть nullable, union или отсутствовать.

Внутри метода можно использовать локальные переменные, встроенные функции PHP, константы своего класса, другие методы своего класса (`self::helper()`, `$this->helper()`), рекурсию и `throw`.

Есть два пути передачи данных, выбор автоматический:

| Тип в PHP | Как передаётся | Скорость |
|---|---|---|
| `int`, `float`, `bool`, `string` | напрямую | без накладных расходов |
| `array` с докблоком `int[]`, `float[]`, `int[][]`, `float[][]` | одним блоком памяти | копирование, быстро |
| всё остальное: `array<string, int>`, `list<array{...}>`, `?int`, `int\|string`, `mixed`, без типа | через формат `serialize()` и C-рантайм с массивами по правилам PHP | заметные накладные расходы |

Для сложных типов пишите докблок: по нему генерируются тестовые входы.

```php
/**
 * @param list<array{customer: string, amount: float, qty: int}> $orders
 * @return array<string, float>
 */
```

### Что не переводится

- Чтение и запись свойств объекта, вызовы методов других объектов и классов, пользовательские функции.
- `new`, замыкания, генераторы, вывод, `global`, `static`-переменные.
- Параметры и результаты-объекты, `callable`, ресурсы.

Такой метод остаётся на PHP, причина печатается при сборке.

### Eloquent, Doctrine и другие ORM

Код, который обращается к ORM, не переводится: запрос в базу — это вызовы PHP-объектов и ввод-вывод, в C их нет. И время в таком методе уходит на запрос, а не на PHP.

Разделяйте: запрос остаётся в PHP, вычисление выносится в отдельный метод.

```php
$rows = Order::query()->where('year', 2026)->get(['customer', 'amount', 'qty'])->toArray();
$totals = Report::totalsByCustomer($rows);   // этот метод можно пометить #[AccelerateToC]
```

Учтите результат бенчмарка ниже: простая агрегация большого списка строк через C выходит медленнее, чем в PHP, потому что передача данных дороже самого вычисления. Выносить в C стоит тяжёлую обработку: циклы над числами, разбор текста, расчёты на каждую строку.

## Выбор модели

```php
use Forja\Model;

#[AccelerateToC]                                   // модель по умолчанию из конфига
#[AccelerateToC(model: Model::OPUS)]               // Claude по API-ключу
#[AccelerateToC(model: Model::LOCAL)]              // локальная модель по умолчанию
#[AccelerateToC(model: 'local:qwen2.5-coder:14b')] // конкретная локальная
#[AccelerateToC(model: 'fast')]                    // ваш псевдоним из конфига
```

```bash
vendor/bin/forja --model=local
```

| Провайдер | Что это | Что нужно |
|---|---|---|
| `anthropic` | Claude через Messages API | `ANTHROPIC_API_KEY` |
| `local` | Ollama, LM Studio, llama.cpp, vLLM — любой сервер с OpenAI-совместимым `/chat/completions` | запущенный сервер; ключ не нужен |

Настройки — в `config/forja.php`; переменные окружения: `FORJA_MODEL`, `FORJA_LOCAL_URL`, `FORJA_LOCAL_MODEL`. Локальные модели ошибаются чаще, но неверный перевод не проходит проверку и в проект не попадает.

## Lock: заморозка удачного кода

```bash
vendor/bin/forja --lock='App\Words::counts'
```

```php
#[AccelerateToC(lock: true)]
```

Замороженный перевод сохраняется, даже когда вы меняете PHP-метод, модель или запускаете `--force`. Его C-файл можно править руками. Проверка при этом не отключается: если после правки PHP результаты разошлись, метод вернётся на PHP, пока вы не поправите C или не снимете замок (`--unlock`).

## Проверка и защита

1. **Прототип выводится из PHP-типов**, а не берётся у модели.
2. **Фильтр до компиляции.** Разрешён короткий список заголовков; `system`, `fork`, `fopen`, сокеты, inline asm отклоняются. Это список запретов, не песочница — ревьюйте `forja/src`.
3. **Сравнение с PHP в отдельном процессе.** Ваши `examples`, границы диапазонов и случайные входы. Segfault убивает только дочерний процесс. Сравниваются значения, типы (`1` и `1.0` — разные результаты), ключи массивов и их порядок.
4. **Канал отказа.** Там, где PHP бросил бы исключение или предупреждение, или где значение не того типа, C отказывается, и выполняется PHP-метод. Перевод, который возвращает значение там, где PHP падает, проверку не проходит.
5. **Валидация аргументов на каждом вызове.** Объекты, непрямоугольные матрицы, слишком большие для копирования значения в C не уходят.
6. **Устаревание.** Если PHP-файл изменён после сборки, загружается оригинал.
7. **Выключатель.** `FORJA_DISABLE=1` или `Forja\Runtime::enable(false)`.

Подсказки для проверки задаются в атрибуте:

```php
#[AccelerateToC(
    ranges: ['n' => [0, 5000], 'text.len' => [0, 400]],
    examples: [['The cat and the hat'], ['']],
)]
```

Логи: `Forja\Runtime::configure(logger: $psrLogger)` при старте приложения.

## Настройка PHP для веб-запросов

В CLI всё работает сразу. Для FPM нужен один из вариантов в `php.ini`:

```ini
; рекомендуемый: ffi.enable остаётся по умолчанию (preload)
opcache.preload=/путь/к/проекту/forja/build/preload.php

; проще
ffi.enable=1
```

Без этого приложение работает на PHP, а в лог пишется причина.

## Команда

```
forja [пути...] [--model=ИМЯ] [--auto] [--dry-run] [--frozen]
      [--lock[=Класс::метод]] [--unlock[=Класс::метод]]
      [--force] [--no-verify] [--strict] [--status] [--config=ФАЙЛ]
```

- `--auto` берёт все подходящие методы с циклами, даже без атрибута; `--dry-run` показывает, что будет сделано, не вызывая модель.
- Статусы: `verified`, `rejected` (не прошёл проверку), `failed` (ошибка генерации или компиляции), `missing` (в `--frozen` нет готового перевода), `unsupported`, `unverified` (`--no-verify`).
- Без `--strict` код возврата всегда 0: неудачный модуль — это метод, оставшийся на PHP, а не сорванный деплой.

## Бенчмарк

```bash
php benchmarks/run.php
```

PHP 8.4.5, Apple Silicon, лучшее из 5 прогонов, мс. C здесь — эталонные переводы из `benchmarks/c/`, написанные вручную, а не ответ модели.

| Метод | PHP | PHP+JIT | PHP+C | C / PHP |
|---|---|---|---|---|
| Mandelbrot 320×240×300 | 250.78 | 18.77 | 16.77 | 15.0x |
| Quicksort, 100 000 чисел | 50.29 | 16.27 | 10.58 | 4.8x |
| Матрицы 120×120 | 42.98 | 5.45 | 2.05 | 21.0x |
| Частоты слов, 2 МБ, встроенные функции | 16.29 | 16.29 | 12.64 | 1.3x |
| Частоты слов, 2 МБ, ручной цикл | 199.43 | 46.03 | 12.79 | 15.6x |
| Суммы по клиентам, 200 000 строк | 20.64 | 15.65 | 84.94 | 0.2x |

Выводы из таблицы:

- Циклы над числами и байтами ускоряются в 5–20 раз.
- Код из встроенных функций (`preg_split`, `array_count_values`) уже выполняется на C внутри PHP; выигрыш небольшой.
- Простая агрегация большого вложенного массива через C **медленнее** PHP: сериализация 200 000 строк стоит дороже самого суммирования.
- Против включённого opcache JIT выигрыш на числовых циклах невелик.

## Ограничения

- Проверка на тестовых входах не доказывает эквивалентность. Задавайте `ranges` и `examples` под реальные данные.
- Значения сложных типов копируются через `serialize()`; при переданном объекте PHP вызывает его `__serialize()`/`__sleep()` до того, как Forja откажется и выполнит PHP-метод.
- Файлы, подключённые через `require` в обход автозагрузки, не ускоряются.
- Windows не проверялся.

## Тесты

```bash
vendor/bin/phpunit
```

Тесты не обращаются к настоящим моделям: C берётся из `tests/c/`, а HTTP-драйверы обоих провайдеров проверяются на локальной заглушке сервера.
